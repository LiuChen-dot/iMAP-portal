# 基因组浏览器模块修复说明

**文档类型**：项目进展说明  
**涉及模块**：基因组浏览器（Genome Browser / genbro 嵌入）  
**修复时间**：2026 年 2 月

---

## 一、问题概述

本地开发时基因组浏览器存在两类问题，导致无法正常加载或报错：

1. **初始化不执行**：iframe 内的 genbro 发送的 "Genbro Ready" 消息早于父页面注册监听，消息被遗漏，`GB.Load(gb)` 从未执行，页面表现为一直加载不出内容。
2. **CORS 跨域**：genbro 直接请求 `https://www.imicap.com:8443` 的 TSV 数据与外部帮助文档，浏览器因缺少 `Access-Control-Allow-Origin` 拦截请求，控制台报错并导致数据加载失败。

---

## 二、修复内容

### 2.1 消息时序与通信逻辑（cytoscape/index.vue）

| 问题 | 原逻辑 | 修复后 |
|------|--------|--------|
| 监听注册时机 | 在 iframe 的 `onload` 回调里才 `addEventListener('message', ...)` | 在 `onMounted` 中**先**注册 message 监听，再设置 iframe.onload |
| 触发条件 | 任意来源的「第 1 次」message 即执行 genBro | 仅当 `event.data === 'Genbro Ready'` 时执行初始化 |
| 兜底 | 无 | iframe.onload 时若尚未初始化且 `window.GB` 已存在，补跑一次 genBro |
| 清理 | 闭包计数器、调试 console.log | 使用 `genBroInitialized` 标志，移除调试输出；`onBeforeUnmount` 移除监听 |

**涉及文件**：`zwportal/src/views/cytoscape/index.vue`

---

### 2.2 本地开发 CORS 与数据源配置

| 问题 | 原逻辑 | 修复后 |
|------|--------|--------|
| TSV 请求地址 | genbro 内写死 `https://www.imicap.com:8443/database/...` | 开发环境改为请求同源路径 `/gb-api/database/...`，由 Vite 代理转发至 imicap |
| 生产行为 | — | 生产环境仍直连 `https://www.imicap.com:8443`，与修改前一致 |
| Help 文档 | 请求失败时可能向 DOM 写入 null 导致报错 | 仅当 `content` 存在时再写入 `#quickhelpcontent`，CORS 失败时静默不显示 |

**涉及文件**：

- **vite.config.js**  
  - `/gb-api` 代理目标改为 `https://www.imicap.com:8443`，并设置 `secure: false`（便于自签名证书环境）。
- **cytoscape/index.vue**  
  - 传入 genbro 的 `gb` 增加：`dataBaseUrl`（生产为 imicap 完整地址，开发为空）、`useGbApiPath`（开发为 true，生产为 false）。  
  - 开发判断：`import.meta.env.DEV` 或 `window.location.hostname === 'localhost'`。
- **public/genbro/genbro.js**  
  - TSV URL 按 `gb.useGbApiPath` 与 `gb.dataBaseUrl` 拼接：开发用 `/gb-api` + 路径，生产用 `dataBaseUrl` + 路径。  
  - Help 加载改为 `if (content && gb.dom.qhelp) ...` 再写 innerHTML。

---

## 三、修复结果

- **本地开发**：刷新后基因组浏览器可正常完成初始化；TSV 经 `/gb-api` 代理请求，不再出现上述 CORS 错误；Help 若跨域失败仅不显示内容，不再抛错。
- **生产部署**：打包后（如打成 JAR 部署）不包含 Vite 代理，`isDev` 为 false，genbro 仍直连 `https://www.imicap.com:8443`，行为与修复前一致，不影响现有线上使用。

## 五、后续建议

- 若生产前端与 `www.imicap.com:8443` 不同源，需在后端配置对应域的 `Access-Control-Allow-Origin`。
- 可考虑将默认物种/replicon 等抽成配置，便于多环境与多数据源扩展（参见《基因组浏览器模块总结与优化建议》）。
