# 基因组浏览器模块总结与优化建议

## 一、当前架构总结

### 1.1 入口与路由

| 入口 | 实际路由/组件 | 说明 |
|------|----------------|------|
| 首页「基因组浏览器」卡片 | `/GenomeBrowser` | 使用 `views/cytoscape/index.vue`（iframe 嵌入 genbro） |
| 基因详情页「Genome Browser」按钮 | `/cytoscape` | 同上，但会先写入 `sessionStorage` 再跳转 |

- **路由配置**：`/GenomeBrowser` 和 `/cytoscape` 都指向 **同一组件** `cytoscape/index.vue`。
- **未使用页面**：`views/GenomeBrowser/index.vue` 仅展示「该功能暂未开放，敬请期待」，当前未被路由引用。

### 1.2 数据流

1. **从基因详情打开**（`Search/Gene.vue`）  
   - 点击「Genome Browser」→ `openCytoscape()`  
   - 从 `proteinData` 中取 `gene_biocyc_id`、`replicon`、`substrains tax id` 写入 `sessionStorage`  
   - `router.push({ path: '/cytoscape' })`

2. **cytoscape 页加载**（`cytoscape/index.vue`）  
   - 挂载 iframe：`/genbro/genbro.html`  
   - iframe 加载完成后，genbro 内执行 `parent.postMessage("Genbro Ready", "*")`  
   - 父页监听 `message`，**仅在第 1 次**收到时调用 `genBro()`  
   - `genBro()` 从 `sessionStorage` 读取 `gene_searchId`、`gene_SubstrainsTaxId`、`gene_replicon`，组装 `gb` 对象，调用 `GB.Load(gb)`

3. **默认参数**  
   - 直接打开 `/GenomeBrowser` 时：`orgid='ECOLI'`，`repliconId='COLI-K12'`，`gene` 为空。

### 1.3 技术组成

- **宿主**：Vue3 单页，`cytoscape/index.vue` 仅负责一个 iframe + Bottom。
- **内核**：`public/genbro/` 下静态资源（genbro.html + genbro.js、gbortho.js、gbseq.js、gbtracks.js、gbmenu.js、gbutils.js、genbro.css），以及 CDN 的 Font Awesome；通过 iframe 加载，暴露全局 `GB`，与父窗口通过 `postMessage` 通信。

## 二、存在的问题与可优化点

### 2.1 路由与命名不统一

- 菜单/首页展示为「基因组浏览器」，链接到 `/GenomeBrowser`，但实现组件在 **cytoscape** 目录下，且基因详情跳转用的是 `/cytoscape`。
- 用户从不同入口进入可能看到同一页面但 URL 不同（`/GenomeBrowser` vs `/cytoscape`），不利于分享、书签与埋点统计。

**建议**：  
- 统一入口为 `/GenomeBrowser`，基因详情页的「Genome Browser」改为 `router.push({ path: '/GenomeBrowser' })`。  
- 若保留 `/cytoscape`，可设为重定向到 `/GenomeBrowser`，避免双 URL。

---

### 2.2 未使用的 GenomeBrowser 视图

- `views/GenomeBrowser/index.vue` 仅显示「该功能暂未开放」，且未被任何路由使用，容易造成误解（以为有独立「未开放」页）。

**建议**：  
- 若短期内不打算做独立基因组浏览器页：删除该文件，或改为重定向到当前 cytoscape 页。  
- 若计划后续在此做新版本：在路由中显式注释「预留」并保留文件，避免与现有 cytoscape 实现混淆。

---

### 2.3 与 iframe 的通信方式脆弱

- 依赖 **任意来源** 的 `postMessage`（`"*"`），且仅用「第一次 message」触发 `genBro()`（通过闭包计数器 `b() == 1`），任何其他消息也会占掉这一次机会，导致 `genBro()` 可能不执行或误触发。

**建议**：  
- 监听时判断 `event.data === "Genbro Ready"`（及可选 `event.origin` 白名单）再执行 `genBro()`。  
- 不要用「第几次 message」控制，改为「仅响应 Genbro Ready」这一种消息类型。

---

### 2.4 硬编码与魔法值

- `cytoscape/index.vue` 中：`orgid = 'ECOLI'`、`repliconId = 'COLI-K12'` 等写死。  
- iframe 高度写死为 `933px`，而 genbro.js 里又按嵌入场景设为 `100vh`，父页与 iframe 高度策略不一致。

**建议**：  
- 将默认 `orgid`、`repliconId` 等提取为常量或配置（如 `genbro.config.js` 或环境变量），便于多物种/多 replicon 扩展。  
- 高度统一：要么父级用 `min-height: 100vh`/flex 撑满，iframe 设为 `100%`；要么由 genbro 内 postMessage 上报「已就绪」后，父级再设置 iframe 高度，避免 933px 与 100vh 混用。

---

### 2.5 控制台与调试代码

- `console.log('111111111111111',gb)` 等调试输出仍在生产逻辑中。  
- genbro.js 内存在 `console.log("GB", ...)`、`console.log("ptools", ...)`。

**建议**：  
- 删除或改为 `import.meta.env.DEV` 下的条件输出，避免生产环境噪音。

---

### 2.6 无用代码与可读性（cytoscape/index.vue）

- `function a() { let a = 0; return function b() { a++; return a; }; }` 仅用于「只执行一次」逻辑，可读性差。

**建议**：  
- 改为 `let genBroLoaded = false`，在收到「Genbro Ready」且未加载过时执行 `genBro()` 并置 `genBroLoaded = true`；或使用 `event.data === "Genbro Ready"` 后直接调用一次并移除监听，逻辑更清晰。

---

### 2.7 错误与加载状态

- 若 iframe 加载失败、或 `GB` 未定义、或 `GB.Load` 报错，用户得不到明确提示。  
- 没有 loading 状态，若 genbro 资源较大，会长时间白屏。

**建议**：  
- 在 iframe 上增加 `@error` 或通过定时检测 `contentWindow.GB` 是否存在，超时则提示「基因组浏览器加载失败，请刷新重试」。  
- 在 iframe 上叠加 loading 遮罩，在收到「Genbro Ready」并执行完 `genBro()` 后再隐藏。

---

### 2.8 标题与 SEO

- `updateCmpTitle()` 会改写 `window.top.document.title`，若用户从基因详情跳转过来，可能覆盖原有标题，且没有在离开页面时恢复。

**建议**：  
- 若需统一为「Genome Browser: …」可保留；否则可仅改 iframe 内 title，保留外层 SPA 标题。  
- 使用 Vue Router 的 `beforeUnmount` 或 `onBeforeUnmount` 在离开 cytoscape 页时恢复默认 title（可选）。

---

### 2.9 安全与依赖

- genbro.html 使用 CDN 的 Font Awesome（`cdnjs.cloudflare.com`），若 CDN 不可用或被篡改，会影响样式与图标。  
- `parent.postMessage(..., "*")` 允许任意 origin 接收，若父页被嵌入到不可信页面，存在理论风险。

**建议**：  
- 关键资源考虑打包到 `public` 或通过自有静态资源服务提供，减少对 CDN 的依赖。  
- postMessage 使用具体 `targetOrigin`（如 `location.origin` 或配置的白名单），父页校验 `event.origin`。

---

### 2.10 移动端与响应式

- iframe 使用 `width: calc(100vw - 20px)` 和固定/大高度，小屏下可能出现横向滚动或可视区域不佳。  
- genbro 内部控件较多，未看到针对移动端的适配说明。

**建议**：  
- 至少保证 cytoscape 容器在小屏下不溢出（如 `max-width: 100%`、避免固定 933px）。  
- 若需支持移动端，可对 genbro 做响应式或提供「简化版」入口（若第三方支持）。

---

### 2.11 可访问性（a11y）

- iframe 无 `title` 属性，读屏软件无法获知内容含义。  
- 基因详情页「Genome Browser」为 div 点击，无键盘可聚焦与 role。

**建议**：  
- 为 iframe 增加 `title="基因组浏览器"`（或与 i18n 一致）。  
- 按钮改为 `<button>` 或为 div 增加 `role="button"`、`tabindex="0"` 及键盘事件，便于无障碍访问。

---

## 三、建议优化优先级

| 优先级 | 项 | 说明 |
|--------|----|------|
| 高 | 统一路由与跳转 | 基因详情改为跳转 `/GenomeBrowser`，或 `/cytoscape` 重定向到 `/GenomeBrowser` |
| 高 | postMessage 只认 "Genbro Ready" | 避免误触发或只执行一次逻辑失效 |
| 中 | 去掉调试日志、简化「只执行一次」逻辑 | 提升可维护性与生产环境整洁度 |
| 中 | 默认参数配置化、iframe 高度统一 | 便于扩展与一致体验 |
| 中 | 加载失败提示与 loading | 提升体验与可排查性 |
| 低 | 处理未使用的 GenomeBrowser 视图 | 删除或明确用途，避免混淆 |
| 低 | title 恢复、a11y、postMessage origin | 体验与安全增强 |
